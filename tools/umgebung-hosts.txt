# Erlaubte Hosts der Cloud-Umgebung "deeptok-fabrik"
#
# Wohin: Umgebung bearbeiten → Network access → Feld "Allowed domains".
#   Stufe "Custom" (so heißt sie in der Doku vom 27.10.2026; nennt die App die Stufe
#   mit eigener Liste anders, z. B. "Limited", diese nehmen). Häkchen "Also include
#   default list of common package managers" SETZEN.
#   Die Standardliste deckt schon ab: npm, PyPI, GitHub (auch raw.githubusercontent.com),
#   *.googleapis.com (Chrome-Download für HyperFrames, Google-Fonts-CSS),
#   fonts.gstatic.com (Schriftdateien) und die Ubuntu-Paketquellen.
# TTS-Anbieter brauchen KEINEN Eintrag: Hosts, die bei den Network secrets stehen,
#   sind automatisch erreichbar.
#
# Das Feld will eine Domain pro Zeile. Falls es keine Kommentare annimmt,
# nur die Hosts herauslösen und einfügen:
#   grep -v '^#' tools/umgebung-hosts.txt | grep -v '^$'
#
# Ein führendes "*." deckt laut Doku JEDE Subdomain ab, auch mehrstufige.
# Jede Änderung dieser Liste baut den Cache neu: Das Setup-Skript läuft dann
# einmal erneut (rund 40 s). Die Reihenfolge beim Einrichten ist deshalb egal.
#
# Offen für das Go/No-Go: Mit dieser Stufe erreicht die Sitzung keine anderen
# Hosts. Ob das auch für WebFetch im Faktencheck (G3) gilt, einmal mit einem Host
# außerhalb der Liste testen. Danach festlegen: entweder Network access "Full",
# oder jede Quelle (src) im Faktenblatt muss auf einem Host dieser Liste liegen.
#
# Geprüft am 27.10.2026 (Erreichbarkeit und Weiterleitungen mit curl).
